# input-svc

입구입니다. 스택에서 일어난 모든 일이 여기서 기록(`input.records`)이 되고, 소비자별 배달 행이 함께 만들어집니다.
기록을 쓰는 프로세스는 이것 하나입니다. 소비자는 `gocommon/queue` 로 표를 직접 읽습니다.

| 경로 | 하는 일 |
|---|---|
| `input.outbox` | 서비스가 INSERT 만 하는 받은편지함. 비우면서 봉투를 확인하고 기록+배달을 한 트랜잭션에 쓴다 |
| `POST /records` | 데이터베이스가 없는 프로세스(손님 에이전트, 수집기)의 입구 |
| `POST /mind/{경로}` (PUT·PATCH·DELETE) | 화면의 쓰기. 기록을 남기고 mind 의 결정적 레인이 한 결과를 읽어 답한다. mind 가 내려가 있으면 202 로 답하고 기록은 남는다 |
| `POST /chat/messages` | 대화에서 한 말. 기록(`chat.message`, 글은 봉인)이 되고 에이전트가 큐에서 집는다. `GET /chat/messages/{키}` 로 글을 읽는다 |
| `/last` | 소스별로 새 소식이 마지막으로 온 때와 점검(`check.result`)의 최신 값. 상태 탭이 읽는다 |
| `/held` | 다섯 번 실패해 따로 둔 메시지 |
| `/turns`, `/workout` | 대화와 운동의 투영 |

## 투영 둘

대화 턴과 운동 세션은 **기록을 화면이 읽기 좋게 둔 표**입니다. 쓰기는 기록과 표를 한 트랜잭션에 남기므로, 저장한 사람이
바로 읽어도 자기 말이 있고, 기록과 표가 어긋나지 않습니다. 판단은 없습니다. 고른 기록을 날짜·종류로 보여 줄 뿐입니다.
손님 것은 손님 기록(`input.guest_records`)으로 갑니다.

옛 내역은 표가 원본입니다. 새 내역은 기록에서 다시 만들 수 있습니다.

### 대화 (`internal/chat`)

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/turns` | 대화 전체, 오래된 것부터. `?limit=60[&before=<턴 id 또는 atIso>]` 면 그 앞의 최신 60개와 `hasMore`(콘솔의 페이지) |
| POST | `/turns` | 한 턴 추가. id 와 시각은 여기서 발급. 기록 `chat.turn` |
| PUT | `/turns/{id}` | `origin` 이 있는 턴(작업 카드)의 문단을 바꾸고 시각을 지금으로. 대화의 말은 못 바꾼다 |

- 턴의 글은 기록에 **봉인해서** 둡니다(`MESSAGE_KEY`, mind 의 `MIND_CONTENT_KEY` 와 같은 값). mind 는 기록을 받아 봉인을 열고
  대화방 하나로 읽습니다(`sensor.Messages.TakeTurn`).
- 라이브 SSE 스트림과 "턴이 진행 중인가"는 에이전트에 있습니다. 재시작을 넘겨 살아남지 않는 것이 의도입니다.
- 손님 토큰은 `guest` 스레드만 읽고 씁니다.
- `turns.proposal_id` 에는 외래키가 없습니다([017](../db/migrations/017_turns_soft_proposal_ref.sql)). 조인할 키가 아니라 가리키는 값입니다.
- `origin`(060)은 턴이 대화 세션이 아니라 작업·알림에서 왔다는 표시입니다. 실행 하나에 턴 하나: 뒤의 말이 PUT 으로 앞의 말을 갱신하고
  맨 아래로 내려옵니다. 콘솔은 접힌 카드로 그립니다.
- 콘솔은 `limit`·`before` 로 창을 요청합니다. 서비스가 말없이 씌우는 상한이 아니라 UI 가 요청하는 창이라, 과거를 잃어버린 것처럼 읽히지
  않습니다. `before` 는 화면 맨 위 턴의 id 입니다(시각의 `+09:00` 은 Cloudflare 경유 길에서 공백이 돼 버렸다, 2026-10-19).
- `at` 은 날짜 없는 벽시계("15:04"), `atIso` 는 전체 타임스탬프입니다. 벽시계는 Postgres 가 `to_char(at at time zone $1, 'HH24:MI')` 로 만들어서
  컨테이너의 `TZ` 에 기대지 않습니다.
- 턴은 이미 일어난 일입니다. 저장이 실패해도 에이전트는 SSE 로 발행하고(로컬 id 를 붙여서) 오류를 로그에 남깁니다. 그 턴은 새로고침하면 사라집니다.

### 운동 (`internal/workout`)

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/workout` | 책 전체 (운영자·손님 같은 책) |
| POST | `/workout/changes` | 바뀐 세션만. 세션 id 로 쓰므로 두 사람이 서로 지우지 않는다. 기록 `workout.changes` |

- 세트 단위까지 정규화했습니다. jsonb 한 칸에 넣으면 "3주간 하체 볼륨"을 물을 때마다 기록 전체를 끌어올려야 합니다.
- **파생값은 저장하지 않습니다.** 볼륨·1RM 추정·연속일은 전부 계산해서 냅니다. 실제로 기록한 세트와 어긋날 수 있는 두 번째 숫자를 만들지 않습니다.
- `content_hash`: 바뀌지 않은 세션의 자식 행은 건드리지 않습니다.
- `client_id`: 화면이 만든 종목 id 를 지킵니다. 저장할 때마다 id 가 새로 나면 React 키가 전부 갈립니다.
- `muscle_group` 은 쓸 때 박습니다. 표(`muscle`)를 나중에 고쳐도 지난 3월의 하체 볼륨이 바뀌지 않아야 합니다.
- 루틴을 세션보다 먼저 저장합니다. 순서가 뒤집히면 같은 요청의 새 루틴을 가리키는 세션이 조용히 `routine_id = NULL` 이 됩니다.
- mind 는 `workout.changes` 를 받아 끝난 세션을 발생으로 읽습니다(`sensor.Structured`). 손님이 저장한 것은 손님 기록이라 mind 의 운영자 쪽으로 가지 않습니다.
