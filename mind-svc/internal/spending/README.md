# 가계부

카드사가 카카오톡으로 보내는 결제 알림을 읽어 분류하고, 월별로 더하고, 예산과 견줍니다.
따로 된 서비스가 아니라 mind 안에 있습니다. 표는 `mind.card_transactions` 등이고, 읽기는
mind 의 창구(`/api/spending/...`), 고치는 일은 명령(`spending.write`)입니다.

## 어디서 읽나

카톡 DB 를 직접 열지 않습니다. 수집기는 메시지마다 봉인해서 스트림에 넘기고(`message.received`),
구조화 레인이 봉인을 연 뒤 이 패키지에 건넵니다(`internal/sensor` 의 `Messages`). 원문은
기록(`input.records`)에 봉인된 채 남습니다.

- 이름에 "카드"가 들어간 1:1 채널만 봅니다. 단체방에서 친구가 "승인 났어 12,000원"이라고
  쓴 건 결제가 아닙니다. 다른 채널은 `SPENDING_EXTRA_CHANNELS` 로 더합니다.
- 카카오페이 같은 간편결제 채널은 일부러 뺐습니다. 카드로 결제되면 카드 알림과 두 번 잡힙니다.
- **맥의 카카오톡이 켜져 있어야** 알림이 들어옵니다. DB 에 메시지를 쓰는 것이 카톡 앱입니다.
  카톡 메시지가 `SPENDING_STALE_AFTER`(기본 12시간) 넘게 없으면 화면이 경고합니다.
- 같은 메시지를 두 번 읽어도 줄은 하나입니다(`source_ref` = 메시지 id). 놓친 구간은 소비자 배달 행을
  다시 넣으면 다시 읽힙니다.

## 읽는 방법

알림 형식은 카드사마다, 같은 카드사도 알림톡과 문자가 다릅니다. 그래서 템플릿을 맞추지
않고 금액·일시·가맹점을 생김새로 찾습니다(`internal/parse`).

- 일시(날짜+시각)가 없으면 결제가 아니라고 봅니다. 광고와 공지는 원화 금액은 있어도
  시각이 거의 없습니다.
- 결제처럼 보이는데 가맹점이나 금액을 못 찾으면 **추측하지 않고** `spending_unparsed` 에
  넣습니다. 화면에 "읽지 못한 알림"으로 뜨고, 사람이 적거나 버릴 때까지 남습니다.
- 카드사 방의 메시지를 기록하다 실패하면 스트림이 다시 시도합니다. 데이터베이스가 답하지 않는 동안은 횟수를
  세지 않고 기다리고, 그 메시지만 다섯 번 실패하면(`gocommon/queue` 의 규칙) 격리함으로 빠져 뒤의 알림이 막히지
  않습니다. 상태 탭의 '기록 · 처리하지 못한 기록'에 보입니다.
- 달러 결제는 assets-svc 가 시간마다 남기는 환율(`assets.fx`)로 원화를 추정하고 `estimated` 로 표시합니다. 하루 넘게
  환율이 없으면 사람이 적도록 읽지 못한 알림으로 보냅니다. 다른 통화도 그렇습니다.
- 파서를 고친 뒤 다시 읽히려면 해당 `card_transactions` 행을 지우고 그 기록을 다시 배달하면 됩니다.

## 취소

전액 취소는 같은 금액, 90일 안, 같은 가맹점이나 같은 카드인 가장 최근 승인과 짝을 짓고
둘 다 합계에서 뺍니다. 목록에서는 줄을 그어 남깁니다 — 폰에 온 알림과 목록이 맞아야
하니까요. 짝이 없는 취소(부분 취소)는 돌려받은 돈으로 음수가 됩니다.

## 분류

키워드 규칙(`category`)이 처음 분류를 하고, 화면에서 고칠 때 "이 가맹점은
앞으로도"를 켜면 분류 캐시(`mind.classes`, `merchant.rule`)에 운영자의 값으로 남아 그 가맹점의 지난·다음 내역에 적용됩니다.
하나씩 손으로 고친 내역(`category_source = manual`)은 일괄 변경이 덮어쓰지 않습니다.

규칙도 가르친 가맹점도 못 맞혀 '기타'로 남은 결제(`category_source = rule`)와 '기타'인 상품은
mind 의 슬롯(`merchant.category`, `internal/mind/charges.go`)이 읽습니다. 모델의 판단을 엔진이 등급으로 바꾸고,
카드 없이 적거나 값을 채워 묻거나 빈칸으로 묻습니다. 반려하면 기타를 손으로 정한 것(`manual`)으로 남겨
다시 묻지 않습니다.

## 투자 계좌에서 쓴 돈

카드 알림은 업비트·한투에서 뺀 돈을 계좌이체나 현금으로 쓴 것을 보지 못합니다. assets-svc 가
출금마다 다른 투자 계좌로 다시 들어갔는지 짝을 찾고, 못 찾은 것은 에이전트가 카드로 묻습니다
(`agent/internal/module/assets/ask.go`). 거기서 "지출"로 답한 몫은 assets-svc 가 목록이 바뀔 때 전부 기록으로 남기고
(`assets.outflows`), 구조화 레인이 그 목록에 맞춰 `source = 'asset'` 줄을 맞춥니다(`assets`). 줄 이름(`source_ref`)은 답한 시각까지 담아서, 다시 답하면 옛 줄이 빠지고 새 줄이
들어옵니다. 그대로인 줄은 건드리지 않으므로 가계부에서 고친 분류·합계에서 빼기는 남습니다. 지우기는
자산 탭에서 다시 묻는 것으로 합니다(여기서 지워도 다음에 다시 들어옵니다). 목록이 없는 기록은
아무것도 바꾸지 않습니다. "카드값"으로 답한 출금은 넣지 않습니다 - 그 결제는 카드 알림으로 이미 있습니다.

## 묶음 가맹점: 무엇을 샀나

카드 알림에는 "쿠팡 8,900원"까지만 있습니다. 쿠팡 결제(쿠팡이츠 제외)는 들어올 때
`enrich_status = pending` 이 되고, **에이전트가 백그라운드에서** 그 사이트의 주문목록을 읽어
상품별로 나눕니다(`card_transaction_items`). 자세한 동작은 에이전트 쪽
`agent/internal/module/spending/enrich.go` 에 있습니다.

- **네이버페이** 주문내역은 결제와 같은 도메인에 있습니다. 브라우저 결제 안전장치는
  `browser/payment-hosts.json` 의 `view` 에 적힌 내역 페이지(호스트+경로 정확히 일치, GET 만)만
  묻지 않고 통과시키고, 나머지는 여전히 묻습니다. 백그라운드 작업 중이면 묻지 않고 거부합니다.
- 에이전트는 1분마다 `GET /api/spending/enrich/pending` 만 봅니다. 대기 건이 있을 때만 Claude 세션을
  띄웁니다. 두 번의 조회 사이에는 최소 10분 간격을 둡니다(봇 차단 대비).
- 카드 금액과 상품 금액이 다르면 장부가 맞춥니다(`enrich.Allocate`). 쿠폰·캐시로
  덜 냈으면 비율대로 나누고, 배송비로 더 냈으면 "배송비·기타" 한 줄을 더합니다. 3배 넘게
  차이 나면 다른 주문으로 보고 거절합니다.
- 상품이 있는 결제는 분류별 합계를 상품 기준으로 셉니다. 총액은 여전히 카드 금액입니다.
- 못 찾으면 30분, 3시간 뒤 다시 시도하고, 세 번째에 `not_found` 로 끝냅니다.
- 로그인 화면이 나오면 그 사이트의 대기 건 전부가 `login_required` 로 멈춥니다. 화면 탭에서
  로그인한 뒤 가계부의 "다시 시도"를 누르면 이어집니다.

## API

경로는 모두 mind 의 `/api/spending` 아래입니다. GET 은 창구에서 바로 읽고, 나머지는 명령입니다: 에이전트는 기록을
남기고 답을 읽으며(`mindcmd`), 화면은 mind 의 문으로 와서 같은 기록을 남깁니다.

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/health` | 읽지 못한 알림과 반복 작업. 토큰 불필요 |
| GET | `/spending?month=YYYY-MM` | 한 달 요약·분류·일별·내역 + 정기 결제·읽지 못한 알림·수집 상태 |
| POST | `/transactions` | 직접 적기 (현금 등) |
| PATCH | `/transactions/{id}` | 분류(`remember`)·메모·합계 제외·금액(추정·수기만) |
| DELETE | `/transactions/{id}` | 수기 내역만. 알림에서 온 것은 `excluded` 로 뺍니다 |
| PUT | `/budgets` | `{category, amountKrw}`, category `""` 은 전체. 0 은 삭제 |
| POST | `/unparsed/{id}/resolve` · `/dismiss` | 읽지 못한 알림을 적거나 버림 |
| GET | `/enrich/pending` | 지금 조회할 묶음 결제(에이전트용) |
| POST | `/transactions/{id}/items` | 주문 상품 기록 — 금액은 서버가 카드 금액에 맞춰 나눔 |
| POST | `/transactions/{id}/enrich-report` | `not_found` · `login_required` · `failed` |
| POST | `/enrich/retry` | `{source}` 로그인 후 재개, `{id}` 한 건 다시 조회 |
| PATCH | `/items/{id}` | 상품 분류 고치기 |
| GET | `/unclear?days=45` | 분류를 물을 것: 규칙이 기타로 둔 결제·기타인 상품(최근 순, 취소·제외 빼고)과 고를 분류 목록 |
