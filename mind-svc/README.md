# mind-svc

jarvis 를 **인지 루프** 하나로 다시 짠 실험 서비스. 기능마다 서비스를 붙이는 대신
인지의 단계로 나눈다.

```
감지 → 관측 로그 → 해석 → 세계 모델 → 주의·스킬 → 자율성 관문 → 행동
                              ↑                                │
                              └─────── 행동의 결과도 관측 ──────┘
```

| 층 | 패키지 | 하는 일 |
|---|---|---|
| 감지 | `internal/sensor` | 카톡·iMessage 수집기를 rowid 로 읽어 관측으로 남긴다. 판단하지 않는다. 원문은 content 저장소, 로그엔 ref 만. **구조화 소스**(`structured.go`)는 규칙으로 발생을 만든다: 가계부의 결제와 그 안의 상품(쿠팡), 운동 세션, Immich 사진(시각·도시·찍힌 사람·즐겨찾기), 캘린더(일정으로도 동기화: 대화의 일정이 이미 그 항목이면 그쪽이 말하고, 지워지면 취소. 상대의 개인 항목은 `owner: partner` 로 표시해 내 하루로 치지 않음), 자산(보유·입출금·매도, 시세는 읽지 않음, 5분마다), 맡긴 작업(jobs-svc), context-svc 영역 체류. 카카오페이·토스 방의 "받았어요" 알림은 송금 발생. 소스마다 고정 구간만 읽고 바뀐 것만 관측한다. **소스마다 읽는 곳은 하나**(`records.go`): 같은 읽기를 memory-svc 에 구조화 기록(`POST /records`, 모델 없이 그래프에 바로)으로 넘겨, memory-svc 는 이 소스들을 다시 읽지 않는다. 문구와 엣지 키는 예전 수집기 그대로라 그래프가 이어진다. 보낸 내용의 해시만 `mind_records`(048)에 두어 바뀐 것만 다시 보낸다 |
| 관측 로그 | `internal/obs` | 스택에선 events-svc(outbox → `POST /consume`), 로컬에선 프로세스 안의 로그. 다시 재생할 수 있다 |
| 해석 | `internal/interpret` | 대화를 **덩어리로**(방이 조용해지면) 읽고, 그 방의 일정·고리와 장기 기억이 그 사람에 대해 아는 것을 함께 LLM 에 준다. 변경과 기억할 사실마다 원문 줄 번호와 인용을 받고, 인용이 그 줄에 실제로 있어야 믿는다. 단어 목록이 없다 |
| 세계 모델 | `internal/world`, `internal/store` | 일정(plan)과 열린 고리(loop). 모든 변경은 누가·무엇에서 무엇으로·어떤 근거로를 남긴다. 바뀌면 주의 층에 알린다. 일정에는 종류(데이트·캠핑·회식…)·장소 종류·동네가 붙는다 |
| 지금 상황 | `internal/world/now.go` | 진행 중일 수 있는 일정(끝 시각이 없으면 같은 종류의 평균 길이, 없으면 보통 길이), 최근 3시간의 위치 단서(결제·사진), 그리고 "어디서 누구와"의 추정과 신뢰도를 **규칙으로** 계산한다(LLM 없음). 같은 동네·장소의 단서는 올리고 다른 곳의 단서는 내린다. `GET /now` 로 에이전트가 **매 턴 메시지 앞**에 붙이고(직전과 같으면 "같음"으로만, 쓰는 규칙은 지시에 한 번), 0.5 미만이면 추측하지 말고 묻게 한다. 운영자가 jarvis 에게 "집에 왔어"라고 하면 해석기가 그 일정을 끝내 추정이 고쳐진다 |
| 날씨 | `internal/weather`, `internal/mind/weather.go` | 예보는 Open-Meteo, 지명은 OpenStreetMap Nominatim(둘 다 키 없음). 한 번 읽으면 지난 92일(실제로 내린 양)과 앞으로 16일, 다음 36시간은 시간별로 온다. 예보는 30분, 지명은 30일(못 찾은 이름은 하루) 기억하고 Nominatim 에는 1초에 한 번까지만 묻는다. 지명은 일정의 동네 → 장소 → 캠핑장 낱말을 뗀 장소 순으로 찾고("자라섬 캠핑장" → "자라섬"), 같은 이름이 여럿이면 집 근처(±1.5°)를 먼저, 도로·버스 정류장·물길로 적힌 것은 버린다("성수동"은 제주의 버스 정류장이기도 하다). 첫 낱말만으로는 찾지 않는다("카페 하이"의 "카페"는 장소가 아니다). 집은 폰에서 만든 '집' 영역(context-svc `/regions`), 없으면 `MIND_WEATHER_HOME`(기본 서울) |
| 상식·사건 판정 | `internal/link/judge.go`, `mind_thing_classes`, `mind_link_cache` | "이 장작이 그 캠핑을 위한 것"은 두 단계로 판정한다. ① 상식(LLM, 캐시): 특정 구매가 아니라 (상품 분류, 일정 종류) 쌍에 대해 한 번 묻는다(장작×캠핑 0.9, 생수 0.3, 프로틴 0.05). 상품 이름 → 분류, (분류, 종류) → 판정을 따로 캐시해 처음 보는 조합에만 모델을 부른다. ② 사건(규칙): `상식 × 시간 적합도(2주 안, 하루 전이면 0.7) × 배타성(그 물건을 설명할 일정 수로 나눔) × 보강(처음엔 ⅔, 반복되면 오름)`. 처음 링크는 추정(약 0.6). 상식이 0.5 미만이면 같은 종류의 일정 3번 이상 앞서 산 반복이 있어야 링크하고, 0.1 미만이면 반복이 있어도 하지 않는다. 새 상품은 앞으로 2주의 일정만, 새 일정은 지난 2주의 상품만 본다 |
| 자기 노트 | `internal/self`, `mind_notes`, `mind_note_versions` | 나에 대한 문장("캠핑 며칠 전에 장작을 산다", "21시 이후 퇴근한 날은 운동을 거의 안 한다")과 근거·신뢰도·상태(가설/확정/기각)·규칙(예측이 쓰는 기계용 꼴). 사람이 콘솔 "패턴" 탭에서 확인·기각·고친다. 기각한 노트는 다시 만들지 않는다. 고칠 때마다 버전과 이유를 남긴다. 그 노트로 낸 제안을 승인하면 신뢰도가 오르고, 이유와 함께 거절하면 그 이유가 조건이 된다("집에 남았어" → "직전 캠핑 후 남은 경우 제외") |
| 예측·기대 | `internal/predict`, `mind_predictions`, `mind_expectations` | 예측은 기대로 등록될 때 **기한 타이머**(`expect`/`due`)를 건다: 일정의 하루 전·두 시간 전 타이머를 예측 전반으로 넓힌 것으로, 기한이 오면 밤을 기다리지 않고 그때 채점하고 빗나가면 놀라움으로 그날 밤 성찰에 넘긴다. 준비물 예측은 기한 사흘 안의 첫 아침 07시에 선행 타이머(`lead`)가 아직 안 산 것을 꺼낸다. 아침 07시: 어제 예측을 채점하고(Brier), 오늘·내일 운동(최근 4주 같은 종류의 날 + 그날 해당하는 노트), 앞으로 2주 일정의 준비물(노트의 반복)을 예측해 기대로 등록한다. 새 일정이 생길 때도 그 일정의 준비물을 예측한다. 들어온 발생은 **열린 기대를 키로만** 대조한다. 기한 2~3일 전에도 채워지지 않은 준비물은 카드로("11/15 캠핑. 지난번엔 3일 전에 참나무 장작 10kg(2만 원)을 샀어요. 담아둘까요?", 근거: 지난 구매와 지난 일정의 대화), 승인하면 장바구니에 담기만 하는 작업(jobs-svc). 내일 운동이 낮고 오늘이 괜찮으면 저녁 요약에 한 줄("하체를 오늘(수)로?", 묻지 않음) |

에이전트가 `/usage` 로 넘겨 웹 헤더의 사용량 막대에 "판단용 API (mind)" 한 줄로 보인다(오늘/상한, 이번 달, 용도별).

`/api` 와 콘솔은 메모리 모드에서만 토큰 없이 열린다. 스택에서는 서비스가 `Authorization: Bearer $API_TOKEN`,
사람은 콘솔 전용 토큰 `MIND_CONSOLE_TOKEN` 으로 한 번 `/?token=…` 을 열면 HttpOnly 쿠키를 받고 주소창에서 토큰을 지운다.
그 쿠키로는 콘솔 경로만 열리고, 서비스 전용 경로(`/consume`, `/status`)는 서비스 토큰만 받는다. 맥북에서 맥미니의 콘솔은
`scripts/mini console`(ssh 터널 로컬 18102 → 맥미니 8102, 토큰은 화면에 찍지 않고 한 번 로그인). 로컬 8102 는 `scripts/mind` 가 쓴다.
스택은 `API_TOKEN` 이 비면 뜨지 않는다(로컬 시험만 `API_TOKEN_OPTIONAL=true`).
