# status-svc

상태 탭의 판정. "뭐가 고장났나"를 컨테이너가 아니라 기능 단위로 답한다.

## 경계

**읽기만 하고, 기능별 코드가 없다.** 줄은 네 가지뿐이다:

| 줄 | 어디서 |
| --- | --- |
| 프로세스 | 각 서비스의 `/health`(아래 '서비스의 계약'), 그 안의 반복 작업 하나가 사람이 묻는 것이면 그 작업만 따로 한 줄(카톡·iMessage 읽기, 커플 캘린더) |
| 소비자 지연 | 입구 `/health` 의 `deliver:<소비자>` |
| 소스의 기대 주기 | mind 레지스트리의 `source` 구역(소스별 경고·이상 시간과 문구)과 입구 `/last` 의 소스별 마지막 새 소식 |
| 서비스가 남긴 점검 | 입구 `/last` 의 `check.result` 최신 값. 그 일을 볼 수 있는 서비스가 판정해 기록으로 남기고(`gocommon/checks`), 여기는 보여 주기만 한다 |

점검을 남기는 곳: 맥미니의 전제·카톡 로그인·폰의 위치 보고는 context-svc, 계좌는 assets-svc, 주문 내역
로그인은 에이전트, 대화 해석·기억 보내기는 mind. 바뀌었을 때와 한 시간에 한 번 말하므로, 세 시간 넘게 말이
없으면 말하던 쪽이 멈춘 것이라 "모름"으로 바꾼다.

새 소스를 지켜보는 일은 레지스트리 행 하나다(`PUT /api/registry/source/{id}`). 코드가 바뀌지 않는다.
재시작한 어댑터가 첫 읽기를 한 번 더 내도 소식으로 세지 않는다(내용이 같으면 시각을 고치지 않는다).

mind 가 내려가 있어도 소스 줄은 사라지지 않는다. 마지막으로 읽은 레지스트리로 계속 본다.

**소모하는 감시는 하지 않는다.** uniple 리프레시 토큰은 쓸 때마다 회전하고 KIS
토큰은 1분에 하나만 발급된다. 그것을 직접 두드리는 헬스체크는 감시 대상을
망가뜨리는 원인이 된다. 그래서 어댑터가 평소 읽는 일의 결과만 본다.

## 서비스의 계약

서비스는 `GET /health` 를 같은 모양으로 답한다([`gocommon/health`](../gocommon/health/health.go)):
`loops` 는 반복 작업마다 마지막으로 끝까지 돈 때·마지막 오류·연달은 실패·기다리는 가장 오래된 것,
`held` 는 격리함(실패를 거듭해 따로 둔 것)의 수·가장 오래된 것·몇 개의 이름과 이유·처리할 곳이다.
이전 모양(`{"status":"ok"}`)도 그대로 읽는다.

- 서비스의 줄(기반): 200 이고 반복 작업이 저마다 정한 시간 안에 한 번은 끝까지 돌았으면 정상, 그 시간을
  넘기면 이상(멈춤), 세 번 넘게 연달아 실패하는 중이면 주의. 반복 작업은 할 일이 없어도 한 바퀴가 끝나면
  "돌았다"고 적으므로, 실패하지 않고 멈춰 버린 것도 시간이 지나면 이상이 된다.
- 격리함의 줄(격리함): 따로 둔 것이 없으면 정상, 있으면 주의 - 그 목록과 처리할 곳을 펼친 줄에 보인다.
  가계부(읽지 못한 카드 알림), 기록(처리하지 못한 기록), 기억(넣지 못한 사실), 작업(멈춘 작업).
- 기록은 받는 쪽마다 줄이 따로다. 받는 쪽이 꺼졌으면 원인으로 그쪽을 가리킨다.

같은 `/health` 를 여러 줄이 읽으므로 10초 동안 한 번만 읽고, 주소마다 따로 기다린다(느린 서비스가 다른
줄을 붙잡지 않게).

## 원인 연결

각 항목은 `Deps` 를 선언한다. 자신이 이상이고 의존 대상도 이상이면, 가장 깊은
이상 항목을 `cause` 로 돌려준다. 화면은 그것을 "X 때문일 수 있어요"로 적고,
맨 위 문장은 원인이 없는 이상만 센다. 카톡이 꺼져서 카드 알림도 멈춘 것은
한 가지 문제다.

## API

| | |
| --- | --- |
| `GET /health` | 프로세스가 떠 있으면 200 |
| `GET /status` | 항목별 최신 판정 |
| `POST /refresh` | 지금 다시 확인하고 결과를 돌려줌. 느린 항목은 최소 간격을 지킨다 |

서비스 추가는 `internal/probes/probes.go` 의 `All` 에 한 줄, 그 밖의 줄은 레지스트리와 기록에서 온다(`internal/probes/records.go`).
