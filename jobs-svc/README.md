# jobs-svc

대화에서 맡긴 작업의 기록. 포트 8098.

작업을 실행하지는 않는다. 실행은 에이전트의 스케줄러(`agent/internal/module/jobs`)가 한다. 이 서비스는 그 실행이 읽고 쓰는 상태이고, 작업 탭이 보는 곳이다.

## 흐름

1. 대화에서 "이거 중고나라에 올려줘", "가격 내려가면 알려줘" 같은 일을 시키면 모델이 `create_job`을 부른다(`POST /jobs`). 작업은 바로 실행할 차례가 된다.
2. 스케줄러는 `GET /due?limit=4`로 차례가 된 작업을 받아 시작할 수 있는 것을 고른다(사이트가 있는 작업은 대화가 없고 브라우저가 비었을 때, 사이트 없는 작업은 자리가 있을 때 - 대화 중에도). 로그인 대기 중인 사이트를 쓰는 작업과 이미 실행 중인 작업은 빠진다. 응답의 `next`(다음 작업이 제 시계로 차례가 되는 때)까지 자고, 그 사이에는 작업이 만들어지거나 지시·카드 답이 오거나 대화·다른 실행이 자리를 비우면 바로 깬다. 작업 탭에서 바꾼 것(지시, 지금 실행, 다시 시작)은 이 서비스가 `AGENT_WAKE_URL`(에이전트 `POST /jobs/wake`)로 알린다. 스케줄러 자신의 주기(`JARVIS_JOBS_INTERVAL`, 기본 5분)는 안전장치일 뿐이다.
3. `POST /jobs/{id}/runs`로 실행을 열고 백그라운드 CLI를 돌린다. 브라우저 도구 호출 하나하나가 `POST /runs/{id}/step`으로 기록되고, 탭에서 실시간 진행으로 보인다.
4. 실행은 작업용 도구로 다음 할 일을 스스로 정한다.
   - `schedule_next`: 바깥에서 다시 볼 시각. 주기를 따로 말하지 않았어도 목표를 보고 정한다. 최소 10분, 최대 30일. 카드의 답을 보러 오는 데는 쓰지 않는다 - 카드를 기다리는 동안은 에이전트가 거절한다.
   - `ask`: 승인이나 값이 필요할 때 카드를 올린다(`wait`). 승인이든 반려든 카드가 결정되면 `answer`가 오고 작업이 바로 깨어난다(작업이 무엇을 기다리고 있었든). 실행이 다음 할 일을 정하지 않고 끝났는데 답을 기다리는 카드가 있으면 에이전트가 작업을 그 카드에 다시 건다. 결정이 전해지지 않은 채 카드를 기다리는 작업은 에이전트가 30분마다 모델 없이 찾아 그 결정을 전한다.
   - `request_login`: 사이트 로그인 카드를 올린다. 그 사이트의 작업은 결정될 때까지 쉰다. 반려되면 사이트를 풀고 그 사이트의 작업에 반려로 전해, 로그인 없이 할 수 있는 만큼 하게 한다.
   - `finish`: 작업을 끝낸다.
   - `report`(notify=true)·`finish` 가 대화에 남기는 말은 그 실행의 **작업 카드** 하나로 간다(chat-svc `turns.origin`, 뒤의 말이 앞의 말을 갱신). 대화 세션은 건드리지 않고, 다음 대화 턴이 `[작업 소식]`으로 받는다.
5. `POST /runs/{id}/end`로 실행을 닫는다. 다음 할 일을 정하지 않았거나 오류가 났으면 15분 뒤 다시 시도하고(카드를 기다리는 작업은 시각이 아니라 그 카드의 답이 깨운다), 세 번 연달아 그러면 멈춘다(`failed`). 멈춘 작업은 이 서비스의 격리함이다(`gocommon/health` 의 규칙 - 시도 한 번이 모델 실행 한 번이라 다섯 번이 아니라 세 번): `GET /health` 가 운영자의 멈춘 작업을 세어 상태 탭의 '격리함 · 작업'에 보이고, 작업 탭의 다시 시작(`resume`)이 다시 보내기, 그만두기(`cancel`)가 버리기다. `GET /health` 는 때가 지난 지 두 시간 넘게 실행되지 않은 작업도 세어(에이전트의 스케줄러가 돌지 않는다는 뜻) 상태 탭의 '작업 서비스'를 이상으로 만든다. 대화에 양보한 실행은 횟수에 넣지 않고 5분 뒤 다시 하되, 연달아 양보할수록 두 배씩(최대 1시간) 늦춘다. 실행 중에 지시나 카드 답이 왔으면 실행이 무엇을 정했든 바로 다시 차례가 된다(응답의 `again`).

탭은 `GET /jobs`, `GET /jobs/{id}`로 보고, `instruct`(지시 추가), `run`, `pause`, `resume`, `cancel`로 조작한다. 작업이 끝나고 30일(`JOBS_PURGE_AFTER`)이 지나면 첨부 사진은 에이전트가 지운다.

## 테이블

| 테이블 | 내용 |
| --- | --- |
| `jobs` | 목표, 지시, 사이트, 사진, 상태, 다음 실행 시각, 한 줄 현황 |
| `job_runs` | 실행 한 번. 다음 할 일을 정했는지(`decided`)와 결과 |
| `job_events` | 진행 기록(동작, 메모, 보고, 카드, 지시, 오류) |
| `job_memory` | 실행 사이에 남기는 메모(올린 글 주소, 알아낸 절차) |
| `job_records` | 작업이 지켜보는 대상(글, 매물, 택배)의 현황 |
| `job_inbox` | 사람이 건넨 지시와 카드 답. 다음 실행이 읽으면 소비됨 |
| `job_sites` | 사이트별 로그인 대기 |
