# workout-svc

운동 기록. 웹의 라우트 핸들러 하나 + 볼륨의 JSON 파일이었던 것이 서비스가
됐습니다. 저장소는 Postgres 이고, **바깥으로 나가는 계약은 그대로입니다** —
책 전체를 주고받습니다.

계약을 같이 바꾸지 않은 것은 의도입니다. 분리와 계약 변경을 한 번에 하면
무언가 안 될 때 용의자가 둘이 됩니다.

## API

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/health` | Postgres 를 ping 합니다. 토큰 불필요 |
| GET | `/workout` | 책 전체 |
| PUT | `/workout` | 책 전체 대체 |
| GET | `/stats` | 룰 게이트용. 공백 일수·루틴 상태·주간 부위별 볼륨·진행 중 세션 |

`/health` 외에는 `API_TOKEN` 베어러가 필요합니다. 웹은
`web/src/app/api/workout/route.ts` 가 서버측에서 프록시하므로 브라우저는
토큰을 보지 않습니다.

## 저장 방식

세트 단위까지 정규화했습니다. jsonb 한 칸에 넣으면 룰 게이트가 "3주간 하체
볼륨"이나 "이 종목 최고 세트"를 물을 때마다 기록 전체를 애플리케이션으로
끌어올려야 합니다. 그 질문들이 선제 제안의 재료입니다.

**파생값은 저장하지 않습니다.** 볼륨·1RM 추정·연속일은 전부 계산해서 냅니다.
실제로 기록한 세트와 어긋날 수 있는 두 번째 숫자를 만들지 않는다는 기존
결정을 그대로 따릅니다.

### 왜 content_hash 가 있나

화면은 기록이 바뀌면 **책 전체를** PUT 합니다(600ms 디바운스). 세션마다
종목·세트를 지우고 다시 넣으면 세트를 한 번 체크할 때마다 수천 행이 오갑니다.

세션 내용의 해시를 행에 들고 있으면 바뀐 세션만 다시 씁니다. 운동 중에
바뀌는 것은 대개 진행 중인 세션 하나뿐이라, 나머지 수백 세션은 자식 행을
건드리지 않습니다.

### 왜 client_id 가 있나

화면은 종목마다 `e-<ts>-<i>` 형식의 id 를 만들어 쓰고, 세트를 고칠 때 그
id 로 찾습니다. 서버가 그 id 를 버리고 `(session_id, ord)` 만 남기면 저장할
때마다 id 가 새로 발급되어 React 키가 전부 갈립니다. 600ms 마다 저장되는
화면에서는 이게 눈에 보입니다.

### 부위는 기록 시점에 박습니다

`muscle_group` 은 종목 이름에서 읽을 때 추론하지 않고 쓸 때 저장합니다.
추론 표(`internal/muscle`)를 나중에 고쳐도 지난 3월의 하체 볼륨이 바뀌지
않아야 합니다.

## 기존 기록 옮기기

한 번만 하면 됩니다. 여러 번 돌려도 같은 결과입니다.

```bash
docker compose --profile import run --rm workout-import
```

볼륨의 `/data/workout.json` 을 읽어 PUT 합니다. **원본은 지우지 않습니다** —
화면에서 기록이 제대로 보이는 것을 확인한 뒤에 지우세요.

## 개발 중 따로 띄우기

```bash
cd workout-svc
DATABASE_URL='postgres://jarvis:<암호>@127.0.0.1:5432/jarvis?sslmode=disable' \
  LISTEN_ADDR=:8091 go run .
```

`DATABASE_URL` 이 없으면 부팅을 거부합니다. Postgres 없이 이 서비스가 할 수
있는 일이 없습니다.

## 검증한 것

실제 컨테이너로 확인했습니다.

- 기존 `workout.json`(실제 기록 3세션)을 옮긴 뒤 GET 한 결과가 원본과 동일.
  유일한 차이는 `note: ""` 가 생략되는 것 — 화면에서 같게 보입니다
- 같은 책을 다시 PUT 하면 종목 행이 다시 쓰이지 않음 (해시가 같음)
- 한 세션만 바꾸면 그 세션만 다시 쓰임 (다른 세션의 행 id 가 유지됨)
- `routineId` 가 보존됨 — 루틴을 세션보다 먼저 저장해야 했습니다. 순서가
  뒤집혀 있던 동안, 같은 요청에 함께 온 새 루틴을 가리키는 세션이 조용히
  `routine_id = NULL` 로 저장됐습니다
- `sessions` 가 없는 본문은 400 이고 기록은 그대로 — 파싱 실패 한 번이
  기록 전체를 지우면 안 됩니다
- 토큰 없는 요청은 401, `/health` 는 통과
- `/stats` 의 공백 일수·루틴 상태·주간 부위별 볼륨이 SQL 정의와 일치

## 고친 것

`navigator.sendBeacon` 은 POST 밖에 보낼 수 없는데, 기존 라우트는 GET 과 PUT
만 내보내고 있었습니다. 탭을 닫아서 기록을 flush 하는 경로가 405 를 받고
있었다는 뜻이고, 그 flush 가 막으려던 바로 그 경우에 마지막 세트가 조용히
사라지고 있었습니다. 프록시가 POST 를 PUT 과 같은 대체로 받습니다.
